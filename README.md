## Правила и навыки AI-помощника

Для подготовки к кросс-чеку предусмотрен отдельный маршрут [финальной проверки и сдачи](.agents/rules/acceptance.md): сверка ТЗ, DESIGN.md, истории TDD, деплоя и материалов PR.

Открывай `country-search` как рабочую папку Codex для обнаружения проектных инструкций и навыков. При запуске из родительской `rsschool` можно явно попросить прочитать `country-search/AGENTS.md` и нужный `SKILL.md`. Если новый навык не появился в клиенте, перезапусти сессию в папке проекта. Markdown-правила читаются по ссылкам из AGENTS.md; настройки разрешений запуска команд не менялись.

Формат и обнаружение сверены с официальной документацией OpenAI: [навыки](https://learn.chatgpt.com/docs/build-skills), [AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md). Проектные правила не являются файлами [политики запуска команд](https://learn.chatgpt.com/docs/agent-configuration/rules).

## Стек

TypeScript и DOM API, обычный CSS, `fetch` и `AbortController`, компиляция через `tsc` в ES-модули. Выбран Vitest; для проверки кода и Git-хуков предусмотрены ESLint, Prettier, Husky и lint-staged. Пакетный менеджер — npm.

Обязательные требования ТЗ, наши решения и текущий статус настройки каждого инструмента: [стек проекта](docs/STACK.md).

## Настройка и запуск

Локальный Git подключён к созданному приватному репозиторию. Начальный коммит `594e4fa` опубликован в `main` и содержит только `.gitignore`. Проверенный каркас и документация сохранены отдельным коммитом `291c4de` в ветке `country-search`; она отслеживает `origin/country-search`.

Установка проверена с Node.js 24.14.1 и npm 11.11.0. Все 10 выбранных инструментов установлены локально как точные `devDependencies`; создан `package-lock.json`. `node_modules/` и результат компиляции `dist/` исключены из Git.

Для повторной установки по lock-файлу используйте `npm ci`. В ограниченной среде для кэша npm можно передать `--cache ./node_modules/.cache/npm`; отдельная настройка проекта для этого не требуется.

Установлен TypeScript 6.0.3, совместимый с выбранным typescript-eslint. Проверенный набор версий записан в [стеке](docs/STACK.md). Доступны команды:

```powershell
npm run typecheck
npm run build
```

Обе команды прошли: `typecheck` проверяет типы без записи результата, `build` создаёт `dist/main.js` в формате ES-модуля. Ошибки компилятора возвращают ненулевой код; включён `noEmitOnError`.

Для локального запуска из корня проекта в первом терминале выполните:

```powershell
npm start
```

Команда сначала собирает TypeScript и при успехе запускает http-server по адресу **http://127.0.0.1:8080/**. Сервер раздаёт корень проекта, поэтому доступны `dist/main.js` и CSS из `src/styles/`. Кэш отключён; сервер слушает только локальный адрес.

Во втором терминале включите перекомпиляцию при сохранении TypeScript:

```powershell
npm run dev
```

Дождитесь сообщения `Found 0 errors. Watching for file changes.`. После сохранения `.ts` компилятор обновляет `dist/`; изменения CSS доступны напрямую. Страницу обновляйте вручную. Остановка — `Ctrl+C` в каждом терминале. Сборщик приложения и автоматическая перезагрузка страницы не добавлялись.

HTTP-загрузка HTML, JS и CSS и повторная компиляция проверены. На текущем этапе страница пустая: `main.ts` содержит только заготовку точки входа, CSS — комментарий. Браузер также запрашивает отсутствующую `favicon.ico` с ответом 404; это известное ограничение каркаса.

Vitest, ESLint, Prettier, Husky и lint-staged настроены. Доступны проверки:

```powershell
npm test
npm run lint
npm run format:check
```

`npm run format` применяет форматирование. Prettier сохраняет LF и отступ в два пробела из `.editorconfig`; зависимости, результат сборки, покрытие и копия ТЗ с лицензией исключены из обработки.

Vitest ищет `src/**/*.test.ts` и запускает логику в Node без DOM. Пока тестов приложения нет, допустим успешный пустой запуск. В будущих тестах сеть заменяем через `vi.stubGlobal('fetch', ...)`, время контролируем через `vi.useFakeTimers()`; конфигурация очищает mock-вызовы, восстанавливает spies и stub-глобалы. Пустой запуск не подтверждает работу поисковой логики.

При `npm ci` скрипт `prepare` подключает Husky; в существующей установке его можно повторить через `npm run prepare`. Pre-commit запускает только локальный lint-staged: ESLint и Prettier для staged JS/TS, Prettier для остальных поддерживаемых файлов. Тесты в pre-commit не запускаются, поэтому красный этап TDD можно сохранить. Pre-push выполняет `npm test` и останавливается при ошибке. Сгенерированная `.husky/_/` не хранится в Git; окончания строк хуков закреплены в `.gitattributes`.

Оба хука проверены через `git hook run`, без настоящего push и лишних коммитов. Контрольный зелёный тест с моками fetch/таймерами прошёл; красный assertion остановил pre-push и не помешал pre-commit. Проверочные изменения восстановлены.

`npm audit` сообщает о 10 уязвимых пакетах уровня moderate в цепочках ESLint и typescript-eslint из-за транзитивного minimatch. Ограничение зафиксировано в [прогрессе](docs/progress.md); выбранные прямые версии сохранены, автоматическое изменение зависимостей не выполнялось.

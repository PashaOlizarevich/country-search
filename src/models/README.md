# Модели данных

`country.ts` описывает модель UI с полями для карточки и подробностей. `demoCountries.ts` содержит демонстрационную Японию с локальным флагом и два вымышленных примера для длинных и неполных данных; это не схема ответа API и не рабочие результаты поиска. Неизвестные значения обозначаются `null`; пустой список границ означает известное отсутствие сухопутных границ.

`rawCountry.ts` отдельно описывает проверенную по [реальным ответам](../../tests/fixtures/README.md) часть сырого контракта, нужную будущему преобразователю. Успешный ответ — массив объектов: `name` и `capital` являются строками, `languages` и `currencies` — массивами объектов. `flag` содержит emoji, URL изображения находятся в `flags.svg` и `flags.png`. Поле `borders` у Японии отсутствует; отсутствие поля не следует автоматически считать известным пустым списком границ. `description` в сохранённых ответах отсутствует.

Тип не заявляет полноту схемы всего сервиса: дополнительные поля реальных ответов сохранены в fixtures, а необязательные поля нужны для обработки неполных данных. Это описание формы после проверки, а не проверка внешнего JSON: результат `response.json()` на границе должен оставаться `unknown` до сужения типа. Принудительное приведение к `RawCountryResponse` недопустимо.

`mapCountryResponse.ts` преобразует один `unknown` объект в `Country`: проверяет корень и название, нормализует optional-поля, копирует массивы и выбирает HTTP(S)-изображение из flags.svg/png. Невалидный корень или название вызывает TypeError. HTTP 404 обрабатывается API-слоем до разбора JSON, поскольку тело ответа — обычный текст.

Слой не обращается к DOM и сети. Преобразование покрыто тестами на fixtures и неполных/повреждённых данных.

# Стек проекта Country Search

Основание: [локальная копия ТЗ](TASK.md). Распределение кода по модулям описано в [архитектуре](ARCHITECTURE.md).

Здесь разделены обязательные требования задания и наш выбор среди разрешённых вариантов. Указанный инструмент считается настроенным только после установки и успешной проверки.

## Обязательные технологии по ТЗ

| Технология | Назначение и требования |
| --- | --- |
| TypeScript | Вся логика и интерфейс приложения |
| DOM API | Создание разметки из кода; `body` содержит только скрипт; динамические `innerHTML` и `insertAdjacentHTML` запрещены |
| `fetch`, `Promise`, `async/await` | Асинхронные запросы и обработка результатов; обязательна проверка `response.ok` |
| `AbortController`, `AbortSignal` | Настоящая отмена активного запроса при каждом изменении ввода |
| `AbortSignal.timeout` и `AbortSignal.any` либо ручной эквивалент | Таймаут и объединение причин отмены; таймаут обрабатывается отдельно от своей отмены |
| countries.dev | Публичный API: `GET https://countries.dev/name/{query}`, без ключа; свой backend или прокси не создаём |
| Jest или Vitest | Тесты без реальной сети, с моками `fetch` и управляемыми таймерами |
| ESLint | Проверка кода |
| Prettier | Форматирование кода |
| Husky и lint-staged | `pre-commit` запускает только lint-staged с ESLint и Prettier; `pre-push` запускает `npm test` |

Самостоятельно реализуем `debounce`, а при выполнении бонуса — кэширование. Готовые библиотеки вроде lodash для этих задач не используем.

## Наш выбор для проекта

| Часть | Выбор | Статус |
| --- | --- | --- |
| Интерфейс | Обычный TypeScript и DOM API, без UI-фреймворка | Есть пустая точка входа `src/main.ts`; интерфейс предстоит создать |
| Оформление | Обычный CSS | Создан `src/styles/index.css` с комментарием-заготовкой |
| Компиляция | `tsc`, ES-модули, без сборщика приложения | Подготовлен `tsconfig.json`: строгие проверки, `src/` → `dist/` |
| Пакетный менеджер | npm | Создан `package.json`; зависимости не установлены, lock-файла нет |
| Тестовый инструмент | Vitest — выбранный вариант из двух разрешённых | Ещё не добавлен в зависимости и не настроен |
| Проверки и форматирование | ESLint и Prettier | Ещё не добавлены и не настроены |
| Git-хуки | Husky и lint-staged | Ещё не добавлены и не настроены; минимальная main опубликована, локальная ветка country-search создана |
| Локальный HTTP-сервер | http-server | Версия выбрана; пока не установлен и не настроен |
| Публикация | Статический хостинг, например GitHub Pages | Конкретная площадка пока не выбрана |

ТЗ не требует сборщика и допускает компиляцию через `tsc`. CSS и выбор Vitest — наши решения для этого проекта. Версия TypeScript объявлена в [package.json](../package.json): **6.0.3**, но установленного пакета пока нет.

Node.js используется для инструментов разработки; само приложение работает в браузере. В README зафиксированы обнаруженные при создании каркаса Node.js 24.14.1 и npm 11.11.0. ТЗ не задаёт конкретных версий Node.js и npm.

## Дополнительно для бонуса

`localStorage` используем для истории последних запросов, если приступим к бонусной части. Кэш и объединение одинаковых одновременных запросов реализуем самостоятельно. Сейчас эти возможности не реализованы.

## Проверки и порядок разработки

Для обязательной логики соблюдаем TDD и FIRST: сначала отдельный коммит с падающими тестами, затем отдельный коммит с реализацией. Для гонки запросов нужен отдельный тест, мок которого действительно поддерживает отмену.

Сейчас в `package.json` подготовлены `build` и `typecheck`. Требуемые ТЗ скрипты `lint`, `format`, `test` добавим вместе с установкой и настройкой соответствующих инструментов. До установки TypeScript компиляция также недоступна.

Следующий этап — согласовать установку зависимостей и довести инструменты до рабочего состояния. Этот документ фиксирует стек; новых пакетов при его добавлении не устанавливалось.

# План реализации Country Search

Работать по [ТЗ](TASK.md), [стеку](STACK.md), [архитектуре](ARCHITECTURE.md) и [дизайн-проекту](DESIGN_PROJECT.md). Завершённые этапы отмечать здесь, результаты контрольных точек — в [прогрессе](progress.md).

Внутри этапа выполнять связанные действия без промежуточного согласования каждого шага и макета. Комплексные проверки проводить только в контрольных точках ниже; повторять их после исправлений затронутого поведения. Для обязательной логики сохраняется локальный цикл TDD: падающий тест → реализация → зелёный тест, с отдельными коммитами по ТЗ. Разрешения на Git, установку пакетов и публикацию регулируются [общими правилами](../.agents/rules/workflow.md); уже полученные разрешения повторно не запрашивать.

Для макетов и UI использовать Build Web Apps `frontend-app-builder`, для браузерных контрольных точек — `frontend-testing-debugging`.

## Логическая часть

9. [ ] Через TDD реализовать четыре обязательные части: `mapCountryResponse`, `searchCountries(query, signal)`, собственный `debounce` и различение ошибок. Покрыть неполные данные, кодирование запроса, передачу signal, 404 как пустой результат, HTTP/сетевые ошибки, AbortError/TimeoutError, задержку и отмену debounce. Для каждой части сохранить отдельные тестовый и реализационный коммиты по ТЗ.

10. [ ] Через тесты реализовать состояние и контроллер в `src/search/`: немедленный abort и отмену debounce при вводе, поиск после паузы, таймаут, очистку, повтор актуального запроса и уничтожение. Старые ответы и catch/finally не должны менять новое состояние; собственная отмена не показывает ошибку. Логика не зависит от DOM.

# Интерфейс Country Search

## Контекст

Прочитай [AGENTS.md](../../../AGENTS.md), [прогресс](../../../docs/progress.md) и нужный раздел [дизайн-проекта](../../../docs/DESIGN_PROJECT.md). Применяй [общие правила](../../rules/workflow.md), [архитектуру](../../rules/architecture.md), [интерфейс](../../rules/ui.md) и относящиеся к изменению [проверки](../../rules/testing.md).

## Выполнение

1. Определи затронутый компонент и состояния. Проверь, существует ли он уже, откуда получает данные и как передаёт действия. Не создавай второй контроллер поиска внутри компонента.
2. Для обычного UI используй существующие DOM-модули и CSS. Сохрани токены, размеры и направление дизайн-проекта; для недостающего поведения следуй ТЗ. Новые пакеты не являются условием оформления.
3. При создании интерфейса используй явно демонстрационные данные до подключения логики. При диагностике сначала воспроизведи дефект и изучи DOM, CSS, Console или Network по характеру проблемы.
4. Для задачи на флаг отдельно проверь наличие ассетов, поддержку WebGL и доступность текстуры. Реализуй сцену как изолированный визуальный модуль с остановкой, статичным режимом и очисткой ресурсов; статичный промежуточный результат обозначь честно.
5. Проверь результат в браузере на узком и широком экране, с клавиатурой и затронутыми состояниями. Для сцены добавь reduced motion и отказ текстуры; для сетевого отображения — медленный ответ и отмену. Не проверяй несвязанные сценарии без причины.
6. Если изменение требует нового API или поведения контроллера, примени также навык логики по маршрутизации AGENTS.md и сохрани требования TDD.

## Результат

Сообщи, какое поведение и отображение изменились, что проверено в браузере и что остаётся ограничением. Обнови прогресс; если согласованное визуальное решение поменялось, синхронизируй дизайн-проект. Созданные файлы и предполагаемый вид не заменяют визуальную проверку.

# Country Search — проектные решения

Пункты 9–10 завершены: базовые модули и контроллер проверены отдельно. UI пока использует демоданные; интеграция ещё не реализована.

## 1. Отмена запросов

src/api/searchCountries.ts передаёт полученный AbortSignal непосредственно fetch. Ошибки запроса и чтения тела не перехватываются и сохраняют причину. src/api/errors.ts различает AbortError и TimeoutError по name; HttpError хранит HTTP-статус. Текстовый 404 превращается в пустой результат до response.json(). Тест с реагирующим на signal мок-запросом подтверждает реальную отмену.

src/search/searchController.ts при каждом вводе сначала увеличивает revision, отменяет debounce, освобождает таймер и вызывает abort активного запроса. Новый запрос создаёт собственный AbortController; таймер 10 секунд отменяет тот же сигнал с TimeoutError. Это ручная связка причин отмены, не требующая AbortSignal.any. Таймер начинается после debounce и очищается при завершении, отмене и destroy. Таймаут публикует error даже если переданная функция запроса игнорирует сигнал.

Revision и идентичность active дополнительно запрещают поздним success/catch изменять состояние или освобождать ресурсы нового запроса. Это не заменяет abort: транспорт получает реальный сигнал отмены. Собственная отмена не показывает ошибку. Проверки актуальности после уведомлений и abort учитывают синхронный повторный вход из callback. Отдельная инверсия ответов на уровне mock fetch относится к пункту 11.

## 2. Задержка debounce

src/utils/debounce.ts использует один таймер на обёртку: новый вызов отменяет предыдущий и сохраняет последние аргументы в callback таймера. cancel() отменяет ожидающий вызов. Перед вызовом callback ссылка на таймер сбрасывается, поэтому повторное планирование из callback работает.

Контроллер использует задержку 300 мс по умолчанию: короткая пауза объединяет быстрый ввод, сохраняя отзывчивость. Значение можно переопределить через debounceMs. Без задержки каждый ввод запускал бы запрос, слишком большая задержка ухудшила бы отклик. Debounce самостоятельно не отменяет уже начатый fetch; это делает контроллер немедленно при вводе, до ожидания паузы. retry запускает текущий запрос сразу.

## 3. Сложность

mapCountryResponse обрабатывает одну страну. Время O(S), где S — суммарный размер просматриваемых строк и элементов языков, валют и границ; дополнительная память O(S) для нормализованных строк и новых массивов. searchCountries последовательно преобразует все записи, поэтому сложность линейна по суммарному размеру этих данных. Бонусный кэш отсутствует.

## 4. Разделение ответственности

mapCountryResponse принимает unknown, проверяет данные и возвращает новую модель Country без мутации источника. HTTP-статусы обрабатывает searchCountries, классификацию причин — classifySearchError; эти модули не импортируют UI. Debounce не знает о сети или странах. Тесты используют локальные fixtures, mock fetch и управляемые таймеры.

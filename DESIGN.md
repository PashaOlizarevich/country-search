# Country Search — проектные решения

Пункты 9–13 реализованы: main.ts соединяет API, кэш, историю и контроллер с интерфейсом. Контроллер передаёт актуальное состояние в render; карточки передают уже полученную страну в подробности без нового запроса. При отсутствии результатов сцена показывает подписанный пример Японии.

## 1. Отмена запросов

src/api/searchCountries.ts передаёт полученный AbortSignal непосредственно fetch. Ошибки запроса и чтения тела не перехватываются и сохраняют причину. src/api/errors.ts различает AbortError и TimeoutError по name; HttpError хранит HTTP-статус. Текстовый 404 превращается в пустой результат до response.json(). Тест с реагирующим на signal мок-запросом подтверждает реальную отмену.

src/search/searchController.ts при каждом вводе сначала увеличивает revision, отменяет debounce, освобождает таймер и вызывает abort активного запроса. Новый запрос создаёт собственный AbortController; таймер 10 секунд отменяет тот же сигнал с TimeoutError. Это ручная связка причин отмены, не требующая AbortSignal.any. Таймер начинается после debounce и очищается при завершении, отмене и destroy. Таймаут публикует error даже если переданная функция запроса игнорирует сигнал.

Revision и идентичность active дополнительно запрещают поздним success/catch изменять состояние или освобождать ресурсы нового запроса. Это не заменяет abort: транспорт получает реальный сигнал отмены. Собственная отмена не показывает ошибку. Проверки актуальности после уведомлений и abort учитывают синхронный повторный вход из callback. Отдельный тест `searchRace.test.ts` инвертирует порядок попыток завершения: новый `spain` отвечает раньше старого `sp`; старый мок `fetch` получает abort и отклоняется с `AbortError`, а состояние сохраняет только результат `spain`.

## 2. Задержка debounce

src/utils/debounce.ts использует один таймер на обёртку: новый вызов отменяет предыдущий и сохраняет последние аргументы в callback таймера. cancel() отменяет ожидающий вызов. Перед вызовом callback ссылка на таймер сбрасывается, поэтому повторное планирование из callback работает.

Контроллер использует задержку 300 мс по умолчанию: короткая пауза объединяет быстрый ввод, сохраняя отзывчивость. Значение можно переопределить через debounceMs. Без задержки каждый ввод запускал бы запрос, слишком большая задержка ухудшила бы отклик. Debounce самостоятельно не отменяет уже начатый fetch; это делает контроллер немедленно при вводе, до ожидания паузы. retry запускает текущий запрос сразу.

## 3. Сложность

mapCountryResponse обрабатывает одну страну. Время O(S), где S — суммарный размер просматриваемых строк и элементов языков, валют и границ; дополнительная память O(S) для нормализованных строк и новых массивов. searchCountries последовательно преобразует все записи, поэтому сложность линейна по суммарному размеру этих данных.

## 4. Кэш, общие запросы и история

createCachedSearch в src/api/cachedSearch.ts нормализует ключ trim + toLowerCase. Map хранит до 50 успешных ответов, включая пустой результат, на 5 минут с момента завершения. Ошибки не кэшируются. При переполнении удаляется самая ранняя добавленная запись. Кэш живёт в памяти страницы. Каждый получатель получает structuredClone результата, поэтому мутации не повреждают соседнего потребителя или кэш. Поиск ключа в Map в среднем O(1), нормализация O(Q), копирование ответа O(S); память ограничена 50 ответами.

Общий transport имеет собственный AbortController и набор потребителей. Abort одного потребителя отклоняет только его promise с исходной причиной. Когда потребителей не осталось, запись удаляется до abort транспорта. Проверка идентичности flight не позволяет позднему ответу отменённого транспорта заменить новый flight или заполнить кэш. Завершение уведомляет всех оставшихся потребителей и снимает слушатели.

searchHistory хранит пять последних успешных/пустых запросов, уникальных без учёта регистра, под ключом country-search.history. При загрузке JSON проверяется, пустые/нестроковые/слишком длинные значения отбрасываются. Ошибки доступа и записи не прерывают поиск: остаётся история в памяти. main записывает историю только для актуальных results/empty. Кнопка истории устанавливает ввод и вызывает retry сразу, отменяя debounce; кэш повторного запроса исключает новый fetch.

Для C потребителей одного ответа размером S завершение общего запроса занимает O(C × S): результат копируется в кэш и каждому получателю. В среднем регистрация/отмена потребителя и операции Map/Set занимают O(1), дополнительно нормализация ключа — O(Q). Лимит 50 ограничивает число записей кэша, а не байты или число активных запросов: память кэша — O(K × S), где K ≤ 50, активных потребителей — O(C). Истёкшие записи удаляются при обращении или вытеснении; периодического таймера очистки нет. Порядок вытеснения FIFO по добавлению, не LRU.

История ограничена пятью строками до 200 символов. Обычное добавление и выдача копии ограничены этим размером; первичное JSON.parse занимает O(B) времени и памяти для B байт сохранённого значения, затем clean просматривает элементы до пяти пригодных уникальных строк либо конца массива. Лимит результата не ограничивает размер уже существующего содержимого localStorage.

## 5. Разделение ответственности

mapCountryResponse принимает unknown, проверяет данные и возвращает новую модель Country без мутации источника. HTTP-статусы обрабатывает searchCountries, классификацию причин — classifySearchError; эти модули не импортируют UI. Debounce не знает о сети или странах. Тесты используют локальные fixtures, mock fetch и управляемые таймеры.
